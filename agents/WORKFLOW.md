# Порядок работы агентов

Для задач разработки используйте роли [аналитика](ANALYST.md), [разработчика](DEVELOPER.md) и [тестировщика](TESTER.md). При доступной делегации роли можно передавать отдельным агентам; иначе выполняйте этапы последовательно и явно фиксируйте результаты. Для исправлений только документации достаточно проверки фактов, ссылок и diff без запуска приложения.

1. Аналитик уточняет проблему, изучает код и передаёт разработчику требования и критерии приёмки.
2. Разработчик проверяет реализуемость. При противоречиях возвращает `ANALYSIS_REQUIRED` с причинами и вариантами решения; иначе реализует изменение и передаёт описание и команды проверки тестировщику.
3. Тестировщик проверяет критерии приёмки, негативные и регрессионные сценарии. Возвращает `PASS`, `DEFECT_FOUND` или `BLOCKED` с доказательствами.
4. При `DEFECT_FOUND` разработчик исправляет проблему и снова передаёт результат на проверку. Если исправление выходит за согласованные требования, требуется повторный анализ.

Передача между этапами содержит: задачу, затронутые файлы, ограничения, критерии приёмки, выполненные проверки и открытые вопросы. `BLOCKED` означает, что проверку выполнить не удалось; это не `PASS` и не доказательство дефекта приложения.

Задача готова к ревью после проверки применимых критериев и подготовки PR с описанием результата и ограничений. Не сливайте PR автоматически.
