# Streamlink Twitch GUI

[English](README.md) · [Правила для агентов](AGENTS.md) · [Участие в разработке](CONTRIBUTING.md)

Настольный клиент для просмотра Twitch через [Streamlink](https://streamlink.github.io/) и внешний видеопроигрыватель. Работает в Windows, macOS и Linux. Интерфейс написан на Ember, Handlebars и Less и выполняется в NW.js.

> О состоянии разработки исходного проекта см. [обсуждение upstream #1045](https://github.com/streamlink/streamlink-twitch-gui/issues/1045). Этот репозиторий — форк; ссылки на официальные релизы и wiki ниже ведут в upstream.

## Возможности

- Просмотр трансляций по популярности, играм, каналам и командам.
- Доступ к отслеживаемым каналам после авторизации в Twitch.
- Запуск нескольких трансляций во внешнем проигрывателе.
- Уведомления, горячие клавиши, темы и индивидуальные настройки каналов.
- Фильтрация по языкам и настраиваемые приложения для чата.

## Установка для пользователя

Предварительные сборки этого форка для Windows x64 и Linux x64 доступны в [Releases форка](https://github.com/bespalovnikita/streamlink-twitch-gui/releases). Для Windows скачайте файл `*-win64.zip`, распакуйте архив и запустите `streamlink-twitch-gui.exe`. Официальные сборки upstream доступны в [официальных релизах](https://github.com/streamlink/streamlink-twitch-gui/releases). Подробности установки — в [wiki](https://github.com/streamlink/streamlink-twitch-gui/wiki).

Отдельно установите Streamlink и совместимый видеопроигрыватель, например VLC или mpv. GUI управляет запуском трансляций, но не заменяет Streamlink. Если исполняемые файлы не определились автоматически, укажите пути к ним в настройках приложения.

## Обновление приложения

Переносимые сборки Windows x64 и Linux x64 проверяют новые успешные сборки
`master` этого форка при запуске. В **Настройки → Главная** можно проверить
обновления вручную; там же отображаются текущая сборка, результат проверки и
прогресс загрузки. При отсутствии сети обычная работа приложения продолжается.

Нажмите **Скачать обновление**, а после загрузки и проверки —
**Перезапустить и установить**. Приложение закрывается, помощник заменяет весь
каталог приложения и запускает новую сборку по прежнему пути. При открытых
трансляциях потребуется подтвердить перезапуск: он может прервать просмотр.
Неприменённые настройки нужно сначала сохранить или отменить.

**Позже** откладывает предложение до следующего запуска. **Пропустить эту версию**
скрывает только выбранную сборку; ручная проверка показывает её снова.
После автоматического отката проблемная сборка больше не предлагается при
запуске. Её можно найти ручной проверкой и повторить установку; автоматический
пропуск снимается после подтверждённого успешного запуска этой сборки.

В окне обновления показывается описание изменений. В **Настройки → Главная**
доступны история последних 50 событий и сохранение диагностики в JSON.
Диагностика содержит идентификаторы сборок, время проверок и коды результатов;
содержимое профиля, токены, пути к файлам и сырые журналы в неё не включаются.

Настройки и авторизация хранятся в отдельном профиле и не заменяются. Перед
скачиванием и распаковкой проверяется свободное место. Подпись Ed25519
подтверждает происхождение манифеста, SHA256 и проверка содержимого — целостность
архива. Предыдущая версия приложения сохраняется как резервная копия.
Отдельный снимок данных приложения из localStorage сохраняет настройки,
авторизацию и другие данные моделей перед обновлением. При откате снимок
восстанавливается до загрузки моделей и миграций старой версии.
Если установка или запуск новой сборки не удаётся, помощник возвращает
предыдущую версию.

Папка приложения и её родительская папка должны быть доступны для записи.
Для системных каталогов, установок из пакетов и других платформ используйте
ручное обновление. Первую сборку с этим механизмом нужно установить вручную;
старые сборки, умеющие только открывать страницу релиза, сами его не получат.

## Инициализация рабочей копии

Нужны Git, Node.js и Yarn Classic 1.x. В `package.json` указан Node.js `>=20.9.0`, CI использует версию 20. При выборе более новой версии проверяйте требования закреплённых зависимостей. Если Yarn недоступен, установите Yarn Classic по [официальной инструкции](https://classic.yarnpkg.com/lang/en/docs/install/).

```bash
git clone https://github.com/bespalovnikita/streamlink-twitch-gui.git
cd streamlink-twitch-gui
yarn install --frozen-lockfile --non-interactive
```

Для уже клонированного проекта выполняйте команды из его корня, начиная с `yarn install`. Повторный `git init` и `npm init` не нужны: Git, `package.json`, Grunt и Webpack уже настроены. Используйте существующий `yarn.lock`; если установка сообщает о несовместимости, выясните причину, прежде чем менять зависимости или lock-файл.

При установке нужен доступ к реестру пакетов и GitHub, а при первом запуске/упаковке — к загрузкам NW.js. Глобальная установка Grunt не требуется: `yarn run grunt` использует локальную версию.

## Запуск и сборка

```bash
# Сборка для разработки, запуск NW.js и наблюдение за исходниками
yarn run grunt build
```

Для остановки завершите процесс Grunt сочетанием Ctrl+C. Простое закрытие окна NW.js может привести к его повторному запуску. Инструменты разработчика доступны через кнопку в заголовке окна или `http://localhost:8888/`.

```bash
# Тесты, production-сборка и упаковка для текущей платформы
yarn build

# Только production-бандл, без тестов и упаковки
yarn run grunt clean:tmp_prod webpack:prod
```

Готовое приложение после `yarn build` находится в `build/releases/`; промежуточные файлы — в `build/tmp/`. Полный список задач: `yarn run grunt --help`. Цели платформ задаются явно, например `yarn run grunt release:linux64`; см. `build/tasks/common/platforms.js`. Для сборки Windows-версии в Linux/macOS требуется Wine. Дополнительные инструменты упаковки описаны в CONTRIBUTING.md.

## Проверки

```bash
# QUnit-тесты внутри NW.js
yarn test

# Интерактивный режим тестов с пересборкой
yarn run grunt test:dev

# Покрытие тестами
yarn run grunt test:coverage

# Проверка переводов
yarn run grunt webpack:i18n
```

В Linux без графического дисплея установите Xvfb и запускайте тесты через `xvfb-run --auto-servernum yarn test`. NW.js также требует системных библиотек Chromium. Успешная сборка тестового бандла ещё не означает прохождение тестов: дождитесь результата QUnit.

Для правок только документации проверьте локальные ссылки и `git diff --check`.

## CI и артефакты

GitHub Actions запускает проверки при push и для pull request: QUnit с покрытием
на Linux и Windows, проверки файлов и переводов, production-сборку. Зависимости
устанавливаются с `--frozen-lockfile`; изменение lock-файла при установке запрещено.

В проверках PR и `master` Windows-приложение дополнительно компилируется нативно
на Windows. Готовые файлы доступны в **Artifacts** того же запуска как
`streamlink-twitch-gui-win64-<SHA>`; ZIP артефакта можно распаковать и запустить
`streamlink-twitch-gui.exe`.

После push в `master` (в том числе после merge, squash или rebase PR) задача
`Publish master artifact` выполняется только после успеха всей матрицы `Test`.
Она собирает архив Linux x64 вместе с контрольными суммами. Архив доступен
в разделе **Actions → запуск workflow → Artifacts** под именем
`streamlink-twitch-gui-linux64-<полный SHA коммита>` и хранится 30 дней.
В PR и других ветках эта задача пропускается; при ошибке проверки публикации нет.
Затем `Publish master release` скачивает оба артефакта этого же запуска, упаковывает
Windows-приложение штатным ZIP-скриптом проекта и публикует Linux-архив, Windows ZIP
и общий SHA256 в [Releases форка](https://github.com/bespalovnikita/streamlink-twitch-gui/releases).
Релиз также содержит `update.json`: идентификатор и номер сборки, время коммита,
имена, размеры до и после распаковки и SHA256 архивов обеих платформ. Эти данные сверяются с
`build-info.json`, включённым в сборку. Самообновление использует этот файл,
а не одинаковый для нескольких сборок номер версии `package.json`.
Файл `update.json.sig` содержит подпись точных байтов манифеста. Приложение
принимает только подписи закреплённых в `src/config/update.json` публичных ключей;
ручная проверка также требует действительную подпись. Старые неподписанные
релизы остаются доступны для ручной установки через GitHub.
Каждому коммиту соответствует отдельный предварительный релиз с тегом
`v<версия package.json>-master.g<полный SHA>`; эти файлы не ограничены 30-дневным
сроком хранения артефактов Actions. Повторный запуск не заменяет опубликованные
файлы; незавершённая загрузка остаётся черновиком и может быть повторена.
Релиз создаётся только после успешных тестов и упаковки. Существующая публикация
стабильных upstream-релизов по тегам сохранена отдельно.

### Ключ подписи обновлений

Перед первым выпуском владелец репозитория должен добавить закрытый ключ Ed25519
в **Settings → Secrets and variables → Actions → Repository secrets** с именем
`UPDATER_ED25519_PRIVATE_KEY`. Значение — весь PEM-файл PKCS8, включая строки
`BEGIN PRIVATE KEY` и `END PRIVATE KEY`. В репозитории хранится только публичный
ключ; закрытый ключ не включается в приложение, артефакты и тестовые фикстуры.

Для настройки через GitHub CLI из учётной записи с доступом к Actions Secrets:

```bash
gh secret set UPDATER_ED25519_PRIVATE_KEY \
  --repo bespalovnikita/streamlink-twitch-gui < /path/to/updater-ed25519-private.pem
```

Текущий идентификатор ключа — `master-2026-11-05`. SHA256 публичного ключа в формате
SPKI DER: `9ac28af9492d49501eb2169aa588f6505844395acd64720b86194f2d631f6cae`.
Если секрет отсутствует или не соответствует закреплённому публичному ключу,
публикация прерывается до создания тега и релиза. После настройки можно повторить
неудавшуюся задачу `Publish master release` в том же запуске CI.

При смене ключа сначала выпустите приложение, доверяющее старому и новому
публичным ключам, с подписью старого ключа. После этого переключайте
`signingKeyId` и секрет CI. Сохраните закрытый ключ у владельца для восстановления
настройки CI.

Для запрета слияния без проверок включите в настройках GitHub ruleset для `master`:
обязательный PR и успешные статусы `Test (ubuntu-latest)` и
`Test (windows-latest)`. Сам workflow не запрещает прямые push или слияние
с ошибками; эту политику задают настройки репозитория.
