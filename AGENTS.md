# Инструкции для агентов

## Проект и подготовка

Streamlink Twitch GUI — настольное приложение на NW.js, Ember 3, Handlebars и Less. Сборка использует Grunt и Webpack, тесты — QUnit и Sinon внутри NW.js. Это существующий Git-репозиторий: повторный `git init` не требуется.

Прочитайте [русское руководство](README.ru.md), [правила участия](CONTRIBUTING.md) и [порядок работы](agents/WORKFLOW.md). Команды выполняются из корня репозитория.

- Минимум Node.js: `>=20.9.0` согласно `package.json`; CI использует Node.js 20. Более новые версии сверяйте с ограничениями зависимостей.
- Используйте Yarn Classic 1.x и существующий `yarn.lock`: `yarn install --frozen-lockfile --non-interactive`.
- Не смешивайте npm и Yarn, не добавляйте другой lock-файл. Изменяйте зависимости только в рамках поставленной задачи.

## Карта кода

- `src/app/data/` — модели и слой данных.
- `src/app/services/`, `src/app/utils/` — сервисы и вспомогательная логика.
- `src/app/ui/` — компоненты, маршруты и стили.
- `src/app/nwjs/` — интеграция с настольной средой.
- `src/app/locales/` — переводы; пользовательские строки добавляйте через существующий механизм i18n.
- `src/config/` — конфигурация приложения.
- `src/test/tests/` и `src/test/fixtures/` — тесты и фикстуры.
- `build/tasks/` — Grunt, Webpack, упаковка и запуск NW.js.

## Правила изменений

Сохраняйте архитектуру и совместимость с закреплёнными версиями Ember/NW.js. Не переносите проект на ember-cli и не обновляйте стек без отдельной задачи. Соблюдайте `.editorconfig` и `.eslintrc.json`: UTF-8, LF, табуляция в JS/JSON/Less. Идентификаторы и сообщения коммитов пишите по-английски; новую документацию и отчёты пользователю — по-русски.

Не коммитьте `node_modules/`, `build/tmp/`, `build/cache/`, `build/releases/`, `dist/`, токены и локальные настройки. Не записывайте OAuth-токены в логи или фикстуры. Не меняйте настройки пользователя и не запускайте внешние проигрыватели без необходимости для задачи.

## Проверки и сдача

Для изменений поведения запускайте `yarn test`; при исправлении ошибки добавляйте проверку, воспроизводящую её. Изменения переводов проверяйте через `yarn run grunt webpack:i18n`. Изменения сборки проверяйте через `yarn run grunt clean:tmp_prod webpack:prod`, а упаковки — через соответствующую цель `release`.

В Linux без дисплея тестам нужен Xvfb: `xvfb-run --auto-servernum yarn test`. NW.js может загружаться при первом запуске. Не считайте сборку тестового бандла успешным выполнением тестов: нужен результат QUnit.

Для изменений только документации достаточно проверить локальные ссылки, соответствие команд конфигурации и `git diff --check`. Не заявляйте о пройденных проверках, которые не запускались. Укажите ограничения среды и фактические результаты в PR. Работайте в отдельной ветке; создавайте PR в согласованный репозиторий и целевую ветку. Создание PR не означает разрешение на слияние.
